# MNA Simulation User Guide

This guide explains the normal web-app workflow for drawing circuits, running analyses, and reading results.

## Start From A Demo

- Open `Demo` and choose an amplifier, frequency-domain circuit, SRAM array, or large RLC benchmark. The view zooms to fit the loaded schematic.
- Demos are editable schematics. Move parts, retune values, rename nodes, inspect the generated netlist, and rerun analyses.
- The amplifier demos default to transient analysis with `V(vin)` and `V(out)` selected so the first plot compares input and output directly.

## Build And Edit Schematics

- Use the toolbar to place passives, sources, BJTs, MOSFETs, controlled sources, subcircuits, net labels (`NODE`), and text labels. Placement is sticky like LTspice: every click drops another part, `R` rotates and `E` mirrors the part on the cursor, and `Esc` or right-click finishes.
- Press `W` (or `F3`, or the wire tool button) to draw wires: click a pin, a wire, or empty space to start, click empty space to add a corner, click a pin or a wire to finish. Clicking a wire body splits it so the tap becomes a real T-junction. Clicking any pin also starts a wire without the tool.
- Solid dots mark junctions where three or more connections meet. Amber hollow squares mark unconnected pins and a small amber ring marks a dangling wire end.
- Click or drag to select, `Shift`+click to add, drag on empty space for a marquee. Double-click a part to jump to its Properties. Arrow keys nudge the selection by one grid step (`Shift` for five).
- `R` / `Ctrl+R` rotates, `Ctrl+E` mirrors, `Del` deletes, `Ctrl+C` / `Ctrl+V` copies and pastes, `Ctrl+D` (or `F6`) duplicates, `Ctrl+A` selects all, `Ctrl+Z` undoes and `Ctrl+Y` (or `Shift+Ctrl+Z`) redoes.
- Wheel zooms, right-drag or middle-drag pans, `Space` (or `Ctrl+0`) zooms to fit, `Ctrl + =` / `Ctrl + -` zoom in and out. The View menu also toggles the grid and the automatic net names.
- `NODE` markers with the same name are connected within the same schematic level. `LABEL` components annotate the drawing without adding a part. Anonymous nets show their generated name (`n1`, `n2`, …) once per net.

## Files

- File > Save workspace writes every hierarchy level, the analysis settings, and the netlist mode to a JSON file (`Ctrl+S`). File > Open restores it (`Ctrl+O`).
- File > Export SPICE netlist downloads the canonical netlist generated by the last run (or the raw netlist in netlist mode).
- File > New schematic clears the workspace; the previous state stays in the undo history.

## Use Hierarchy

- Create child levels from the hierarchy panel, then place `SUBCKT` instances on the parent level.
- A child port is an editable `NODE` marker inside the child entity.
- The parent instance uses the child entity's pin list, so port names stay scoped to that entity.
- Renaming a child port updates only instances of that child entity and repairs matching connected wires.

## Run Analyses

- `.op` solves the DC operating point and shows MNA matrices, operating-point values, and device states as lists and tables.
- `.tran` runs nonlinear transient simulation with Backward Euler. Physical BJTs and MOSFETs continue using their I-V equations at each timestep.
- `.ac` first solves `.op`, then linearizes nonlinear devices around that bias and sweeps frequency.
- `.hb` solves steady-state harmonic balance. Supplying a time window reconstructs a time-domain waveform from harmonic-balance coefficients.
- `.dyn` is the frontend dynamic display path. It streams transient samples through the backend websocket.
- API callers that pass options directly: booleans such as `use_krylov` must be `true`/`false` (or `yes/no/on/off/1/0`), counts must be whole numbers, and times/frequencies may use metric suffixes like `"1m"`, as in the netlist directives. Other values return HTTP 400.

## Threads

- Threads in the Simulation panel sets how many worker threads a run may use. `auto` (the default) takes a fair share of the free threads (the budget divided by the number of active runs plus one), but never more than the analysis can use: a small `.op`/`.tran` (fewer than 2048 devices) or a small harmonic-balance run leases one thread, an `.ac` sweep at most half its point count, and a large analysis on an idle server the whole budget; a number is an upper limit. The list goes up to the server's thread budget (`GET /health` → `thread_budget.total`).
- The server enforces one machine-wide budget: `MNA_NUM_THREADS` (default: the CPU count). Concurrent runs share it; a run waits while every thread is in use, so simultaneous requests divide the cores instead of oversubscribing them.
- After each run the status line shows the threads granted and the solver time, e.g. `TRAN complete (ok) · 4 threads · 412 ms`. Result metadata carries `threads_requested` (`auto` or the number asked for), `threads_used` (the grant), `thread_budget_total`, `core_backend` (`cpp`: every analysis runs in the native C++ core), `core_version` (e.g. `0.70.0-dev`), and `elapsed_ms` (wall time of the run on the server). The thread count changes speed only, never results: every analysis gives bit-for-bit the same numbers with 1 or 4 threads.
- Where threads help: `.ac` sweeps (frequencies are split over the threads), `.hb` (time samples and block factorizations), circuits with 2048 or more nonlinear devices (device evaluation), and MOR and Krylov solves on circuits with thousands of unknowns. A transient advances one time step after another, and small circuits run on one thread whatever the setting, because starting threads would cost more than the work.
- Runs started at the same moment proceed side by side when their analyses are numerics-bound: `auto` leases one thread to each small run, and four simultaneous harmonic-balance mixer runs finish in about 1.1x the time of one. A short run (tens of milliseconds) is dominated by netlist parsing, matrix building and result formatting in Python, which concurrent runs on one server take turns at, so four simultaneous small transients take roughly four to five times as long as one (still well under a quarter of a second in total).
- NumPy/SciPy BLAS is always kept to one thread per run.
- API requests pass `"num_threads": "auto"` or a positive integer in `options` (anything else returns HTTP 400); the CLI takes `--threads N|auto`.

## What Changed With The Native Core

The numerical core moved from Python to a compiled C++ extension. Results agree with the old core to 1e-9 relative on linear circuits and 1e-6 on nonlinear and harmonic-balance runs, and the analyses run 3x to several hundred times faster (`PERFORMANCE_PLAN.md`, section 10). A few behaviours changed on purpose; each item gives the old behaviour.

To run the old core, start the server with `MNA_CORE=python` (or the CLI with `--core python`). This works from a source checkout only (see the README, "Start the backend API"). The UI and API work the same way, but every analysis runs in the frozen pre-migration Python core on one thread, and results report `core_backend: "python"`. Option values are still checked by the new rules first, so input the new core rejects with HTTP 400 is rejected in both modes. Values that pass the check reach the old core unchanged, so the old behaviours listed below apply (`use_krylov: "false"`, for example, still switches Krylov on there). Leave `MNA_CORE` unset, or set it to `cpp`, for the native core.

- **Option values are checked strictly.** Booleans such as `use_krylov` take `true`/`false` (also `yes/no/on/off/1/0`, any case), counts take whole numbers (`3`, `"3"`, `3.0`), times, frequencies, and tolerances take numbers or metric strings (`"1m"`), and anything else is rejected with HTTP 400 `INVALID_OPTIONS` naming the option. Old: `use_krylov: "false"` switched Krylov *on* (any non-empty string counted as true), `krylov_rank: 2.7` was silently truncated to 2, and `t_stop: "1m"` or `points: 2.5` failed with an internal type error.
- **Zero means zero.** Only an option that is absent (or `null`) takes its default (`.tran` 0.1 s and 10 µs, `.ac` 1 Hz to 1 MHz with 100 points, `.hb` 8 harmonics). `t_stop = 0` (or `.tran 0`) returns just the initial operating point, `t_step <= 0` is `TRAN_ERROR`, `f_start = 0` or `f_stop = 0` is a DC point, `points <= 0` is `AC_ERROR`, and `harmonics <= 0` is `HB_ERROR`. Old: every zero was replaced by the default, so `.tran 0` ran 10 001 steps to 0.1 s, an AC sweep from 0 Hz started at 1 Hz, and `harmonics = 0` ran with 8.
- **`init_condition`.** `DEFAULT` and `RANDOM` (any case) set the Newton starting point of every nonlinear `.op` and of the initial operating point of every nonlinear `.tran`; a list of numbers is accepted and must have one value per unknown (otherwise `NETLIST_FATAL` "init_condition has k values, expected n (one per unknown)."); any other string is HTTP 400. On a linear circuit there is nothing to start, so the value is ignored and the result's `diagnostics` say so ("init_condition '...' ignored: the circuit is linear, ..."). An array on `.tran` is still the state at t = 0 (no operating point is computed). Old: strings were ignored on linear `.op` and on every `.tran`, lowercase `default`/`random` were rejected, a JSON list failed with an internal error, and a wrong-length array failed with a type error or was ignored.
- **Zero-ohm resistors are a netlist error.** `R1 a b 0` (also `0k`, or a value that underflows to 0) is `NETLIST_FATAL` "'R1' has zero resistance", and a small-signal BJT with `rpi = 0` is "'Q1' has zero resistance (rpi)", reported at once (HTTP 400). Old: a raw "float division by zero" after retrying every gmin step (HTTP 500). Use a small resistance, or a 0 V source to measure a current.
- **The AC operating point honours the Newton options.** `.ac` solves its bias point with the run's `max_iter`, `v_tol`, and `f_tol`, so it is the `.op` solution for the same options and fails where `.op` fails. Old: it always used 10 000 iterations and 1e-9 tolerances, so `.ac` could succeed where `.op` with the same options failed.
- **Linear MOR builds a well-conditioned basis.** The rational Krylov basis is orthogonalized twice (classical Gram-Schmidt, second pass), so it stays orthonormal and the reduced outputs match the full-order solution; on some circuits `mor_basis_size` is smaller than before (11 instead of 13 columns on one test ladder). Old: one pass accepted rounding residuals as new directions; on three random RLC test circuits the basis became numerically singular and the reduced outputs were noise (up to 7e5 V where the true peak is 0.33 V).
- **Threads.** The Threads control, `num_threads`, and the result fields `threads_requested`, `threads_used`, `thread_budget_total`, `core_backend`, `core_version`, and `elapsed_ms` are new (see [Threads](#threads)).
- **Other error reports.** A result that would contain NaN or infinity is `NR_CONVERGENCE` "non-finite solution" (old: returned with status `ok`). A transient step whose matrix is exactly singular is `NR_CONVERGENCE` naming the time of the step (old: a raw linear-algebra error), and gmin stepping still retries it. Gmin stepping retries only numerical failures; netlist and option errors are reported at once instead of after nine rebuilds. `TRAN_ERROR` is a netlist error for Python callers (`NetlistError`; HTTP 400 as before). Harmonic balance refuses a system above its memory bound (`MNA_HB_MAX_NNZ`, default 3e7 stored entries) with `HB_ERROR` "HB system too large (N=..., nnz=...); reduce harmonics" before allocating it.
- **Convergence: junction limiting in `.op` and `.tran`.** When the damped Newton iteration fails or stalls (4 iterations in a row at a damping scale of 1/64 or less), circuits with diodes or BJTs switch to SPICE-style junction voltage-step limiting (`pnjlim`, which moves a forward-biased junction voltage logarithmically instead of linearly) with a monotonicity test as a second acceptance rule. Runs the damped iteration solves without stalling give bit-for-bit the same results as before. A diode directly across a 1 V or 5 V ideal source now converges at gmin 0 to the exact diode current; at 20 V it still fails with `NR_CONVERGENCE`, because exp(800) overflows. Old: a diode across an ideal source never converged (Newton crept about 25 mV per iteration).
- **Convergence: gmin continuation in `.op`.** After a failed `.op` solve the core steps gmin from 1e-2 down to the requested value, each level starting from the previous solution and all levels sharing `max_iter`. The last level must leave a nonsingular Newton matrix, so a circuit that is singular at the requested gmin (a floating island at gmin 0) still reports `JACOBIAN_SINGULAR`. CMOS inverter chains of 4, 6, and 8 Level-1 stages now converge at gmin 0. Old: four stages converged only at gmin 1e-5, with the rails visibly pulled to 1.179 V / 8.5 mV, and six failed at every gmin.
- **Node-to-ground gmin during gmin stepping.** When the server retries a failed solve with growing gmin, gmin is now also stamped from every node to ground (never on branch rows), as SPICE does, besides the stamps across capacitors, diodes, and transistor terminals; the `G` matrix returned for such a run contains them. A floating part of a circuit (for example two resistors connected to nothing else) converges at gmin 1e-12 and sits at 0 V. A node connected only through capacitors is defined by gmin alone, so its DC value moved: the node between two series capacitors from node `b` to ground was at V(b)/2 and is now at V(b)/3. Old: a floating island failed at every gmin step.
- **Level-1 BJT exponent beyond the clip.** Beyond |v/vt| = 80 (about 2.07 V across a junction) the exponential continues as a straight line, `exp(80) (1 + x - 80)` (and `exp(-80) (1 + x + 80)` below -80), so the current and its derivative stay continuous and consistent. Old: the current stayed flat beyond the clip while the reported derivative kept its clip value. Diode exponentials are not clipped, as before.
- **Damped harmonic-balance Newton.** `.hb` first runs the old undamped Newton iteration; only when that breaks down (non-finite residual or singular Newton matrix) does it restart from zero with a damped Newton (residual backtracking plus junction limiting on the sampled junction voltages) for the rest of `max_iter`, so every run that converged before gives bit-for-bit the same result. A string of two forward-biased diodes now has a converging HB solution. Old: it failed with `HB_ERROR` "Singular HB Jacobian.". The `hb_solver` metadata gains the counters `damping_restarts`, `limited_steps`, `damped_steps`, and `undamped_steps`. Damping from the first iteration (the native binding's `damping="always"`) needs far fewer iterations (11 instead of 38 on the GHz mixer) but stops at a slightly different point inside the 1e-6 tolerance, so it is not the default.

## Display Results

- Use Display nodes to choose labels such as `V(out)`, `V(vin)`, or `I(L1)`.
- Empty display selection means all available waveform labels are shown.
- Static runs open draggable result tiles with engineering-notation axes (`2m`, `20n`).
- Dynamic display uses the toolbar play button and streams selected nodes into live tiles. The backend needs a websocket library; `pip install -e .` now pulls `uvicorn[standard]` for this.
- Probe mode lets you click a pin to open a live dynamic tile for that net.

## Krylov Subspace Solver

- Enable the Krylov subspace solver for iterative linear solves on the full MNA system.
- Auto method selection chooses GMRES/Arnoldi for general systems, MINRES/CR for symmetric systems, and CG for positive-definite systems.
- Manual method selection can override the matrix classifier, including choosing Arnoldi for SPD matrices.
- Auto rank resolves after MNA assembly as `ceil(0.5 * matrix dimension)`.
- Manual rank accepts any positive integer.
- For GMRES/Arnoldi the value is the restart or subspace size; for MINRES/CR/CG it is the iteration budget.

## Model-Order Reduction

- Enable MOR when only a few output labels matter in a larger analog circuit.
- MOR outputs are separate from Display nodes. The reduced model returns only MOR outputs; Display nodes must be empty or chosen from that MOR output set.
- Auto method uses output-aware Linear Krylov MOR for `.ac` and linear `.tran`, and TPWL/POD for nonlinear `.tran`.
- Auto order uses the generated MNA dimension plus input/output count: `min(n, max(10, min(120, 4 * (inputs + outputs))))`.
- Result metadata reports both `mor_order` / `mor_resolved_order` as the requested reduction budget and `mor_basis_size` as the actual independent basis size after pruning.
- TPWL/POD is a nonlinear transient MOR path. If it is requested on a purely linear circuit, the backend routes that run to Linear Krylov MOR and reports the route in metadata.
- `.op` and `.hb` are not reduced in this v1; they report metadata explaining that MOR was intentionally bypassed.

## Raw Netlist Mode

- The netlist panel shows the generated netlist for schematic mode.
- Editing the netlist asks for confirmation, clears the schematic hierarchy, and switches the next run to raw `netlist_text`.
- Use raw netlist mode for quick parser checks, `FUNC` source expressions, or circuits that are easier to type than draw.

## Important Model Notes

- Level-1 BJTs and MOSFETs are physical nonlinear defaults.
- `.op` finds the nonlinear bias, `.ac` uses the small-signal linearization around that bias, and `.tran` remains nonlinear.
- The SRAM demo uses Level-1 MOS devices and `FUNC`-driven write, hold, precharge, and read timing.
- The close-tone HB demo is tuned for steady-state beat behavior at GHz carriers where direct transient can be expensive.
- An independent current source `I1 a b ...` drives its current into node `a` (the first node), the opposite of SPICE: `I1 n1 0 DC 1m` with `R1 n1 0 1k` gives `V(n1) = +1 V`. Controlled current sources (`G`, `F`) follow the SPICE sign. The UI, the demos, and the tests rely on this convention.
- `.op` uses only the DC values of the sources: the time-dependent part of `FUNC`, `STEP`, and `COS` sources is left out even when it is non-zero at t = 0. The initial operating point of `.tran` includes it, so the two can differ (`V1 a 0 STEP 2 0` gives 0 V in `.op` and 2 V at t = 0 in `.tran`).

## Practical Troubleshooting

- If a waveform is empty, check that the selected Display nodes exist in the generated netlist labels.
- If a transistor amplifier has no gain, run `.op` first and confirm the device region and DC bias are sensible.
- If a hierarchy error mentions an invalid pin, check that the parent `SUBCKT` instance pins match the child entity's exported `NODE` names.
- If a Krylov subspace solver run is slower on a small circuit, use a larger sparse circuit such as the Large RLC Mesh demo; dense direct solve is often faster for tiny matrices.
